# Administrator MFA: manual assessment

This packet is for a named human assessor using the implemented administrator account pages. It does not replace the separate [pilot relying-party assessment](pilot-manual-assessment.md), automated browser tests or qualified accessibility/security assessment. No manual result is recorded yet. Copy the [result template](administrator-manual-results-template.md), identify the tested revision and retain every unexecuted observation as `not_run` or `blocked`.

## Environment and safe evidence

Follow the [administrator operations runbook](administrator-accounts.md) in an isolated Windows/WSL2 evaluation. Use both PostgreSQL and SQL Server in separately provisioned environments, with `Identity__AdministratorAccounts__Enabled=true` and `Pilot__Enabled=false`. Complete Migrator and protected bootstrap explicitly, then open the real AuthServer HTTPS endpoint. No interactive OAuth relying party is required. A blocked startup/trust prerequisite is a blocked assessment, not permission to bypass TLS, weaken MFA or repair records manually.

Record Windows build, WSL distribution/kernel, Docker/SDK versions, product commit and clean-tree status, database image/provider, browser, authenticator, password-manager and screen-reader versions. Record the assessor and UTC dates. Use an opaque private configuration reference rather than credentials. Synthetic credentials still must not appear in reports, screenshots, HAR, HTML dumps, network logs or speech recordings. Turn off screen/session recording, use an isolated vault/profile and dispose of clipboard history afterward. Never import a personal vault.

Recommended starting cells are Edge/Chromium with NVDA, Firefox with NVDA, Edge's isolated built-in vault, and Firefox with an assessor-selected independent disposable vault. Agree and record the matrix before assessment; unavailable tools remain gaps. These choices are not a verified support declaration. Linux Playwright WebKit does not establish human Safari/VoiceOver or physical-mobile behavior. Qualified assessment must decide additional platforms and justify coverage.

Use light, dark and system-selected themes; keyboard only where specified; desktop and narrow reflow; 200% text resizing and 400% browser zoom; Windows forced-colors where supported. Record actual settings and observations. Do not treat an emulated viewport as a physical-device assessment.

## Cases

Family identifiers refer to the authoritative [MFA-01–13 inventory](../../specs/008-administrator-foundation/mfa-design.md). Manual observations cover only the stated portions; distributed/atomic/upgrade requirements still need their independent automated evidence.

Run each applicable case on both providers and each agreed browser/tool cell. Record observed behavior and expected-versus-actual findings, not simply “looks good.” Fresh interactions expire after five minutes, and five failed attempts can lock the account for five minutes. Keep deliberate error probes below the budget unless testing lockout explicitly; never reset database counters to continue.

Follow the operations runbook when an outcome is ambiguous. A genuinely lost redemption binding may require another unused recovery code; a still-bound setup GET can be reread until its original expiry. Do not spend additional codes solely to simulate a lost setup response. An inability to recover after all factors are lost is a documented product limitation, not a case that should be made to pass by bypassing controls.

## Results and closure

For every provider/tool/case row use exactly `passed`, `failed`, `blocked` or `not_run`. Include actual observations, defect reference, severity, owner, remedial PR/revision and retest lineage. Preserve original failures; a later successful observation does not erase them. No report should include real or synthetic authentication material.

The responsible reviewer evaluates matrix completeness and unresolved findings before accepting the manual scope. Automated source/CI acceptance, human usability/accessibility observations, independent security assessment and certification are separate decisions. Until the required observations are recorded and reviewed, whole-increment T017/T018/T028/T029 acceptance remains open. This packet does not assert WCAG conformance, ASVS verification, NIST assurance levels or OIDF certification.
