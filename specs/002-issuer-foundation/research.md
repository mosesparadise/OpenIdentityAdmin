# Research and decisions

- **Decision: separate credential loading from protocol activation.** OpenIddict 7.7.1 full server options validation requires a grant/response type (`OpenIddictServerConfiguration.cs:62`). Registering a partial live server would advertise incomplete behavior. Keep this slice in framework key/DP services; follow-on Minimal API flows use the actual library pipeline.
- **Decision: do not equate list order with future active signing keys.** Pinned OpenIddict source commit `9146a148b3333570704a0211d037cd318093770a`, `OpenIddictServerConfiguration.cs:543–580`, sorts certificates by validity and descending expiry; `Protection.cs:1469–1485` uses the first credential. A currently valid staged replacement could activate prematurely. Public JWKS staging and token-key selection need their own subsequent protocol acceptance tests.
- **Decision: force lazy protection dependencies.** PersistKeysToFileSystem/ProtectKeysWithCertificate registration alone does not prove persistence, encryption or historical decryption. Validate persisted XML and materialize historical encryptors; execute a protection self-test before listening. Reject plaintext existing rings instead of assuming current settings re-encrypt them.
- **Decision: historical DP decryptors have a different validity policy.** Expiry stops new wrapping but must not make retained encrypted state unrecoverable. Active credentials require current validity; old wrappers still require suitable key type/usage/private material.
- **Decision: compare public key identity.** Certificate thumbprints differ on reissue even if the key is the same. Cross-purpose SPKI hashes catch this reuse.
- **Decision: private Linux filesystem adapter first.** No automatic runtime credential generation, chmod, symlink following or unsupported Windows ACL claim. Import existing PFX with EphemeralKeySet, preserving externally durable storage while avoiding OS-store copies. Future HSM/remote adapters should be driven by actual deployment requirements.
- **Alternatives rejected:** ephemeral runtime keys (restart loss), plaintext DP ring (disclosure), custom encryption format (framework already owns it), new shared library/provider hierarchy (one consumer), fake protocol endpoint (misleading acceptance).

Sources: pinned OpenIddict source above; ASP.NET Core 10.0.12 reference API for IKeyManager/IKey/CreateEncryptor, DataProtectionBuilderExtensions and X509CertificateLoader; independent security and architecture/test reviews on 2026-10-10. No runtime acceptance is inferred from source inspection.

- **Implementation-confirmed PFX decision:** the native loader accepts unencrypted private-key bags even with a nonempty password or a MAC. Two negative fixtures reproduced that behavior. Pin System.Security.Cryptography.Pkcs 10.0.12 directly and inspect for password integrity plus exactly one shrouded key after the native loader's work/count limits. Native export and OpenSSL's normal one-certificate PFX format are the supported input profile.
- **Implementation-confirmed logging decision:** an ordinary parent-category rule loses to provider-specific configuration. A permanent before/after regression requires an enforced options postconfiguration filter, including reload and an unrelated-log positive control.
