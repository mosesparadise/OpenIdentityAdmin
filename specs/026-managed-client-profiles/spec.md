# Managed client profiles, credentials and integration documentation

On 21 November 2026 the user selected M04-B, M04-C and M04-D after the managed application lifecycle delivery. The approved v0.2 requirements FR-02, FR-03, FR-09 and FR-16 govern this batch.

1. A developer can integrate each supported web, browser, native, machine and device registration using its actual protocol flow. Public registrations cannot be issued a shared secret. Browser origin policy and redirect registration are independently enforced. Native applications use exact claimed HTTPS redirects for this batch. Code clients require S256. A machine token has an application subject and authorized API scope and audience. Device polling requires an expiring device transaction and explicit end-user approval. Protected administrator clients retain their independent profile.
2. An authorized administrator can register and replace public client authentication keys with recent MFA, version checks and an atomic audit record. The issuer verifies native client assertions against the current registration and rejects replay. Private key material belongs exclusively to the client. Existing managed web registrations and their credentials survive upgrades on both databases.
3. An administrator can read the integration settings for an eligible registration. Examples identify the actual client ID, exact configured redirect, supported authentication method and PKCE requirement. Configuration refers to the client's secret store. The protected BFF contract and documentation viewers must respect the reader's current permissions. The viewer activation decision requires its existing vendor inventory and clearance evidence.
