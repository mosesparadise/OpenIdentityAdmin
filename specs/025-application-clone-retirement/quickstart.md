# Validation guide

Use pinned SDK/tools and locked restores. Docker must support real PostgreSQL/SQL Server.
Follow existing CI native discovery/provider/browser/contract commands; no in-memory
substitution or relaxed HTTPS/deadlines. Add exact new identities to inventories.
1. Sign in through ordinary Aspire with fresh MFA; create a managed source with exact
   HTTPS callbacks and eligible assignments.
2. Clone with reviewed configuration and new identity/name/future expiry. Observe disabled
   destination/one-time secret, unchanged source and no inherited credential/grants.
3. Separately enable and complete new sign-in/MFA/consent/S256/token/UserInfo/API journey
   across both providers and Chromium/WebKit. Verify secret clearing on hide/expiry/navigation.
4. Change source version or make assigned catalogue policy ineligible during actual observed governance wait. Assert finite
   rejection and independent absence of destination/audit. Exercise save/audit substitution,
   suppression, cancellation, commit and publication faults. Independently reject drift after
   the owned catalogue snapshot is acquired; an eligible edit before that snapshot is allowed.
5. Retire a used app with both permissions/fresh MFA. Observe terminal state, job, list
   exclusion and retained authorized detail/status. Verify old code/new sign-in/UserInfo
   denial, preserved history and reserved client ID.
6. Restart work, remove/restore actor grant authority, explicitly continue stopped work.
   Retirement persists; original approvals/audits remain. Incomplete prior job conflicts.
7. Cover pagination, mutation/issuance races, exact replay versus changed intent, populated
   additive schema upgrades, keyboard/focus, narrow light/dark UI and ambiguous responses.

Retain original artifacts/source identities, run exact-head required CI and independent
reviews. Record failures/limits. Windows/manual, Firefox restoration, historical findings
and external release gates remain open.
