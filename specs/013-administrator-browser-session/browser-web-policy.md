# T007 browser policy and native antiforgery controls

The authorized T005/T007/T008 batch adds the remaining dormant T007 policy layer while preserving the 66 delivered signed identity/state/projection controls. FR-003–008/011/013 and B3-AUTH-03/04, B3-WEB-01–04 are mapped to the existing identity tests and the new `BrowserWebPolicyTests`, `BrowserCookiePolicyTests`, `BrowserAntiforgeryTests` and `BrowserTicketAcceptanceTests`.

Canonical HTTPS identities supply fixed root-relative issuer entry, BFF resume and logout-return destinations. Existing native support for same-origin and canonical non-root identity URIs remains; incoming Host/forwarded headers never supply the trusted origin. Mutation metadata requires HTTPS POST, exact single configured Origin, reviewed URL-encoded media, no query and no Authorization header. Decoded form shape requires exact ordinal single nonempty bounded fields and no files.

Session cookies are host-only Secure/HttpOnly/SameSite=Lax, Path `/`, no Domain and nonpersistent. Generation, prelogin, logout and antiforgery names are distinct from the existing native correlation prefix. Proof purpose strings are separate. Proof cookie lifetime is truncated to whole seconds under its actual server deadline; equality and subsecond remaining lifetime deny publication. Generation proof may use the longer current ticket/context bound, not an unconditional prelogin window. No cookie writer, sliding handler or authentication fallback is activated.

Native ASP.NET Core antiforgery additional data uses an immutable request-owned browser digest/generation snapshot. Real protected token/cookie tests prove that retained old antiforgery cookies do not admit a changed browser or generation. The synchronous provider performs no database I/O and refuses absent snapshots. Future adapters must load durable state asynchronously first and still compare expected generation inside the T005 transaction. Initial generation zero is allowed only after confirmed absence and a newly server-issued or validated protected initial proof; the pure factory cannot establish proof ownership. A missing later generation or storage failure must never become zero.

Every-read policy combines canonical opaque handle, exact browser/ticket association, current generation and actual B1 envelope/lifetime validation. Tests independently break each boundary and verify no activity/generation renewal. Storage unavailability remains a separate outcome owned by the future asynchronous adapter. Partial policy composition remains dormant: production route inventory is still health-only, with no added policy or antiforgery service registration.

These are pure policies, not complete route enforcement. T010/T013 must enforce actual streaming body limits before parsing/native antiforgery, reject pre-parsed bypasses, validate protected browser proof provenance, release cookies only after commit/disposal and retain protocol-specific GET guards. Native OpenIddict correlation ownership is unchanged. Cross-service safe audit correlation and native expiry clamping remain dependent integration obligations.
