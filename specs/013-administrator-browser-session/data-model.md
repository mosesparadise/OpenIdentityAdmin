# B3 owned state and transition model (planned)

This model adds to delivered B1/B2 and the provider plugin structure; no schema change is made by this packet. Exact EF classes/indexes/migrations follow native feasibility and independent review. All times are UTC server observations with existing rollback policy; expiry at equality denies. Never derive authority from browser timestamps.

| Record / owner | Binding and transitions | Bounds |
| --- | --- | --- |
| Browser coordination / Sessions | Random browser proof digest; monotonic generation; current ticket digest reference; revision and last activity. Anonymous context is not identity. Explicit login/replacement advances generation; logout advances it and revokes the current ticket; establishment compares the expected generation. All writers use the same owned ordering. | Maximum 10,000 retained contexts, counting active and tombstoned rows; no eviction of a live ticket or pending operation. Context expires no later than its current ticket/source bound or pending-operation bound. |

All new random selectors are 32 random bytes encoded as canonical unpadded base64url; stored selector digests are SHA-256 with canonical uppercase 64-hex representation. Binding fields have explicit bounded schema lengths and unique indexes; subject/session retain B1's maximum 400 characters. No raw password, factor, assertion, code, verifier or token enters these records except already protected server-owned native/ticket payloads. Account interaction/factor state remains owned by existing administrator features; do not create a parallel MFA store.

## Transactions and race ownership

- Sessions start/replacement locks the browser coordination row in the provider-portable owned transaction, validates generation/revision and quotas, revokes the former ticket if present, and commits intent plus sanitized audit intent together. A failure rolls back the whole local replacement.
- Callback establishes only the exact reserved intent and generation, using the same ordering as logout. B1 persistence must participate in that transaction; independent nested commits are not an acceptable substitute. Reserve quotas before native operations, never hold locks across HTTP, and reconcile ambiguous reservations against durable state without automatic resubmission.
- Platform completion/attachment participates in existing account/profile/native ownership without reversing its established lock order. Native PAR attachment is not authentication; authorization still requires the same browser source session, and exchange still rechecks current authority.
- Logout revokes the bound local ticket and invalidates pending establishment atomically with its audit intent. Remote single-session revocation and its audit commit separately in Platform. Report each outcome independently.
- Active/tombstone/reservation rows all count until safely reclaimed. Capacity check and creation occur under the same owning database coordination, including concurrent instances. At limit, deny safely; do not evict live security state or rely on process-local counters.

## Retention and cleanup

Each invocation deletes at most 100 eligible rows per category. Retain consumed/cancelled markers at least through the latest possible referencing native-state/intent/logout expiry plus the existing 30-second clock tolerance. A cleanup candidate must have no live ticket, pending operation or unexpired native dependency; follow the longer actual dependency rather than a fixed guessed retention period. Source expiry and existing native grace rules may delay cleanup; capacity denial is valid in that case.

The maximum context/ticket dependency is bounded by the original eight-hour/source deadline; shorter operation state remains within its original 300 seconds. Delete children and unreferenced contexts in reviewed order; CAS/revocation and missing-row denial prevent stale resurrection. Cleanup failure retains rows/capacity and grants no authority. Prove before/at/after expiry, concurrent cleanup, failed/unknown commit and quota equality on both providers.

Minimal atomic audit intents are not a complete central audit retention service. Preserve authenticated actor provenance and finite events; later export/retention integration and human assessments remain open. Backup/restore can revive old rows: invalidate affected browser generations and issuer/native state before enabling restored services, and test this consequence without claiming an implemented production automation.
