## Request and authority ownership

The fixed `/account/administrator/browser/login` entry accepts exactly one canonical `Intent`. GET renders native antiforgery and creates purpose-protected anonymous browser/entry cookies without admitting database state. The stable browser proof supplies quota identity; the separate per-intent envelope binds intent, browser, original creation and expiry. Repeated GET preserves the existing envelope and original deadline. Malformed or cross-browser proof cannot reset it. Clearing all cookies cannot prove a prior visit without durable admission; the BFF's original intent and the issuer's one-use durable admission remain required authorities.

The entry envelope lasts at most 300 seconds. Its cookie lifetime is truncated from the actual remaining protected deadline, including fractional clock time. The stable anonymous browser cookie has its own bounded 300-second lifetime and grants no session. Both are Secure, HttpOnly, host-only, root-path, SameSite=Lax, with distinct protection purposes. Neither accepts a submitted client or return URL.

Password and MFA POSTs retain native antiforgery, existing account body/form limits and query-free exact form validation, adding configured exact Origin, HTTPS, POST, URL-encoded media and no Authorization header. Password submission admits the original entry under the existing portable account admission owner, clamping durable expiry to its protected deadline. An explicit wrong-password retry can reconcile only the same pristine pending row, exact browser and exact deadline; this read returns without commit and preserves every original field/audit. Bound, completed, changed or expired state cannot become a new password attempt. There is no automatic retry.

Every sign-in invokes real password and MFA verification. Existing administrator, recovery or pilot cookies do not supply either proof. Dedicated completion checks the exact persisted intent/browser boundary under the native account transaction before consuming OTP. The standalone endpoint explicitly requires absence of browser continuation, so neither page family can complete the other's interaction. Existing T006 continuation integrity and one-use completion ownership remain in force.

Only a real committed private grant supplies completion and the one-shot issuer cookie permit. The original entry is checked before and after awaited cookie issuance; late expiry/cancellation removes new Set-Cookie and returns a safe failure. The redirect contains only `Completion` and uses the configured fixed `/bff/login/resume` destination. Failed audit/unknown commit cannot publish a successful response or trigger a retry. BFF resume, native challenge/callback, source claims and cross-service audit correlation remain T009–T011 work.
