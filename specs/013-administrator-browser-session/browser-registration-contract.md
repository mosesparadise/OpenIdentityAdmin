`AdministratorRegistrationPolicy.ForBrowserSessions()` creates a distinct immutable variant of an already validated B2 policy. It retains the callback, public key and all original grants, requirements, settings and security constraints. Only explicit selection adds native `EndSession`, application profile `administrator-browser-v1` and exactly one return URI at `/bff/logout/return`, derived from the configured HTTPS callback authority. Callback path/query are excluded; nondefault ports and IPv6 authorities are retained. The derived destination must satisfy the original canonical/length/credential/fragment/wildcard URI policy. Callback routes colliding with the reserved return path are denied. There is no configurable arbitrary logout destination or provider-specific branch.

The shared API scope remains `administrator-v1`. Each variant rejects the other's application descriptor. Exact matching preserves enabled-only semantics, rejects extra properties/permissions/settings, private-key contamination and PAR removal, and compares the return URI ordinally. Native legacy `ept:logout` compatibility does not qualify as the product B3 manifest. Existing B2 creation, initialization and live admission callers remain unchanged; no product caller selects the variant.

The existing six native end-session cases now persist the actual B3 descriptor through their test-only manager update. Before accepted validation, a fresh owned scope rereads both application and scope through the actual managers and requires exact B3 acceptance and B2 rejection. Fixed independent expected destinations and existing validation/denial/snapshot oracles remain intact. This fixture update is not an audited registration upgrade.
