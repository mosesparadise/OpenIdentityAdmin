## Behavior and integration limits

`ProtocolHttpBoundary` owns a nonstreaming invocation through staged output, actual native completion, cleanup and publication. One ten-second original request budget remains active through real HTTP sending. Its watchdog aborts transport even when native work ignores cancellation. The delegate still awaits the actual operation and retained cleanup before returning: its HttpContext, scoped services and an enclosing concurrency permit cannot be released while work still uses them. This establishes an abort boundary, not guaranteed delivery or a ten-second bound on server work completing. Noncooperative work can retain a slot beyond the abort; no task is detached to manufacture a fast return.

The adapter stages status, reason, headers, cookies, stream and pipe output and runs bounded reverse-order OnStarting callbacks while owned services remain alive. Unsupported completion/file/unbuffered operations fault admission. Upgrade, WebSocket, extended CONNECT and response trailers are hidden during the finite invocation; replacement of the staged response/body/cookie graph fails admission. It is an explicit fixed-protocol adapter, not general-purpose middleware for arbitrary streaming endpoints or code holding pre-existing live response-feature references. Production composition does not call it.

Internal staging caps are 64 KiB of body, 16 KiB of header name/value content plus per-value accounting, 32 headers and 16 callbacks. These bound this dormant adapter; they do not certify complete B2 response compatibility or change approved protocol rules. Header arrays are copied on input and output; synchronous body/header mutations are atomic. Asynchronous producers and callbacks remain retained even if their task is abandoned. Independent cancellation, unsupported operations and overflows are terminal even when caught downstream.

Read-only publication requires no recorded explicit write phase. Committed publication requires every recorded phase to report a completed, timely native commit. Unknown, incomplete or rolled-back writes cannot publish staged success. A `NativeError` classification is not trusted as evidence for arbitrary native response bytes: it discards all staging and sends only an empty 503 with `Cache-Control: no-store`. Verified native error-response permits and the actual issuance-commit binding remain future integration work. Failure publication itself starts and flushes under the original watchdog.

The opt-in BFF registration constructs the existing OpenIddictClientService with a narrow provider facade that replaces only the scope factory seen by that singleton. The application root factory remains unchanged. Native-created child scopes synchronously capture a live request capability, activate asynchronously at the installed native client-factory boundary, and inherit the original deadline. Parent transaction, reader, active execution, sibling child or non-leaf dispatch ownership rejects a child before transport admission. Parent storage cannot run during an active child. Native await-using disposal joins actual child completion, including quarantine, before releasing parent admission. Stale ambient capabilities and unbound background metadata calls fail closed. This does not enable automatic background refresh.
