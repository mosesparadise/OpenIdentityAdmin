## Composition and profile isolation

`Features/Setup` composes account services and one native server from independent switches. Administrator accounts alone do not activate administrator protocol. The new strict `Identity:AdministratorProtocol` section defaults disabled; `Enabled=true` additionally requires administrator accounts, durable issuer protection, a canonical HTTPS `RedirectUri`, and a `PublicKey` scalar containing the exact public-only RSA JWK accepted by the explicit initializer. Unknown/nested fields and invalid input receive a fixed startup diagnostic/exit 2. No HTTP startup initializes or repairs native registrations.

The server configures S256/code/query, durable keys and existing lifetimes once. Pilot enablement contributes Basic, its scope, interactive login prompt and native authorization caching. Administrator protocol contributes private_key_jwt, `identity.admin` and native PAR. The final explicit authentication-method configuration runs after ASP.NET's native default registration so administrator-only mode does not accidentally advertise Basic. Existing public `AddFirstPartyPilot` remains a complete standalone pilot composition.

Hosting uses actual pinned native URI resolution/inference for its transport classification. An independent guard after actual native inference rejects configured endpoints that missed their declared boundary, before extraction/manager access. Native case/trailing-slash and absolute scheme/host/port/PathBase semantics are retained; root-relative endpoints do not become PathBase-relative aliases.

Enabled, unambiguous pilot requests retain the existing transport and select legacy stores before managers resolve. Selection is routing only: actual native extraction independently checks the same pilot identity; nested unowned native work must use the exact original transaction/HTTP context. Pilot account-page metadata grants only legacy manager access, not token generation. One-shot pilot bootstrap explicitly selects legacy before resolving its managers. Disabled pilot/unknown/mixed profiles cannot enter this transport. Administrator/discovery/JWKS requests enter the owned response boundary in a fresh scope; endpoint dispatch resolves pilot-only services only for the selected enabled pilot.

Fixed-profile raw guards run before native extraction, including native-owned PAR. They preserve cardinality/case, forbid resource/audience and secret overrides, reject Authorization-header mixing, and require method-appropriate form/query input. Malformed input is `invalid_request`; missing/mismatched client proof is `invalid_client`. These internal error classifications still produce the existing sanitized 503 until the separately verified native-error publication capability is implemented.

The original monotonic request and abort watchdog start before asynchronous raw-form classification. Owned execution receives that exact request, so time spent reading a form cannot renew its ten-second budget. The watchdog remains until actual work/cleanup finishes. Normal committed-success and generic error publication gates remain unchanged.
