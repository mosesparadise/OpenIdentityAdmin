## Issuance completion

`NativeIssuanceCompletionTests` adds twelve PostgreSQL/SQL Server × authorize/token × precommit failure/cancellation/postcommit observation-loss cases. Each starts with a genuine full code exchange. The observer captures the exact issuance child after real PAR/code consumption and before its transaction opens, preserving all native handlers. It records actual native generated artifacts after `AttachTokenPayload`; the exact artifact set is one authorization code or access plus ID tokens, each with real token/authorization identities.

The before-commit callback records the actual EF transaction identity. One mode throws the retained sentinel exception before the provider commits. A second cancels the original request CTS, requires the actual commit cancellation token to observe cancellation, then throws its exact retained cancellation exception. This proves cancellation at the pre-provider-commit boundary, not interruption of a provider operation already in flight. The third throws only in `TransactionCommittedAsync` after the actual provider commits the same captured transaction; it simulates lost application observation, not a dropped database-network acknowledgement.

All modes require exactly one attempt/fault, the exact original exception through production wrapping, no response body/location/cookie and no claimed success. Explicit cancellation must reach the actual HTTP lifetime abort hook; a retained default status after abort is not treated as successful publication. Other faults must return HTTP 503. Independent reads require early native PAR/code consumption to remain Redeemed. For precommit failure/cancellation, no generated credential rows or authorization increment may survive. This independently observes rollback on disposal; production has already marked CommitAttempted and does not issue a definite rollback receipt. Postcommit observation loss requires exact retained token/authorization deltas and Valid status for every observed token. Actual native code/access validation and independent ID-token signature/hash validation require the same token identity, authorization binding and subject. Suppressed artifacts are never presented as client responses or used to resume the failed operation. After disarming injection, a new full code exchange succeeds.

## State creation completion

`NativeClientCreationTests` adds PostgreSQL and SQL Server cases for two separately reached failures. A genuine challenge/authorize/callback exchange first proves the fixture can persist state and exchange credentials. An observer after native `AttachTokenPayload` then captures the next challenge's actual opaque state reference, native token identity, owned Sessions context and EF transaction identity.

For commit-observation loss, the exact context/transaction's `TransactionCommittedAsync` callback throws a single precreated exception after the provider has committed. This simulates loss of the application's successful commit observation; it does not simulate a real dropped database-network acknowledgement. For cleanup failure, a scoped sentinel is constructed before the DbContext and armed only for that generation child. Reverse DI disposal releases the context first; the sentinel independently requires `DbContext.Model` to throw `ObjectDisposedException` before throwing the same precreated exception. This is a post-context-disposal completion failure, not a real DbContext disposal defect or proof that every possible disposable failure drains the whole graph.

Both controls require the original exception identity through production aggregation, exactly one native commit/fault/context disposal, HTTP 503, no authentication, body, redirect or cookie, no extra PAR/token send and unchanged issuer credential rows. Injection is disarmed in `finally`. A separately constructed root imports independently owned copies of the same protected credentials and reads the exact committed state. Actual native reference resolution and cryptographic validation must succeed with the same token identity, state-token type and fixed registration. A fresh independent query requires that row to remain Valid. The baseline and retained state account for two rows, only one redeemed. A new challenge/callback succeeds, producing three rows with two redeemed; the unpublished state remains Valid. The failed operation is never retried and no synthetic callback is fabricated for it.

This reconciles persisted outcome in the fixture after an uncertain application result. It does not provide automatic production reconciliation or OS-process restart evidence. Direct native state validation is not callback eligibility or current-lifetime acceptance: the installed fixed-state expiration handler deliberately defers expiry denial until durable callback consumption.

## Private client diagnostics

`NativeClientLoggingTests` adds one real exchange/replay case per provider with a test-only `ILoggerProvider` installed through the actual client logging factory at Trace. The production fixed-client native transaction `NullLogger` policy remains intact. A Trace marker verifies connectivity, while actual non-control diagnostics must also be captured. Separate synthetic detector controls demonstrate structured-field, scope-field and exception-only leak detection when the rendered message masks those values; capture overflow is detected rather than silently accepted.

Observation-only native handlers retain the actual encrypted state payload immediately after `GenerateIdentityModelToken`, its later opaque reference, nonce, PKCE verifier, request-forgery value, both generated private-key assertions, authorization code, access token and ID token. The real correlation-cookie value and PAR reference are also included. Exact reached counts require one protected/reference state, two assertions and one successful authentication. The same client then rejects callback replay without another PAR/token send. Captured diagnostic messages, exception text and direct structured/scope string fields must contain none of the observed values or their URI/form encodings. Assertions never print captured text or credentials; cookie cardinality uses a scalar check.

Retention is capped at 4,194,304 UTF-16 code units of retained diagnostic text (a character limit, not a byte limit) and overflow fails the control. This is fixed-client in-process native/EF/HTTP-factory diagnostic evidence. It does not claim arbitrary nested object serialization coverage, issuer/access/reverse-proxy log coverage, every encoding/transformation, real HTTPS logging, deployment logging policy or process restart. Synthetic credential/log text stays in fixture memory and is not exported as evidence.
