# Collection contracts

## API and BFF

`GET /api/v1/applications` uses the named native bearer scheme plus current `applications.read`. `GET /bff/api/v1/applications` uses the current protected browser session and explicitly maps only to that API route. Missing/unsupported versions do not route to another major. No CORS or arbitrary proxy path.

Query: optional `search` (literal case-sensitive client-ID prefix, maximum100 characters, no control characters), `page` (canonical decimal1–10000, default1), `pageSize` (canonical decimal1–100, default25). Reject duplicate/unknown keys and body framing; parameter encoding is produced by the BFF, never concatenated from raw input. Search compares protocol identifiers using the provider's ordinal collation, with `%`, `_`, backslash and brackets literal. Fixed stable ascending client-ID order with opaque ID tie-break; no unspecified display-name collation or user-controlled SQL/sort. Search label states “Client ID starts with”. Repeated pages are stable for unchanged data; concurrent catalogue mutations do not promise a multi-request snapshot.

200: `{ items: [{ id, clientId, displayName, clientType }], page, pageSize, hasNextPage, expiresAt }`. `expiresAt` is the minimum original access/source idle/absolute deadline, additionally clamped to the original BFF browser deadline; the UI clears its observation at that instant. Query pageSize+1 rows; no separate count/snapshot inconsistency. Allowlisted safe fields only, nullable displayName/clientType where native metadata is absent. Explicit UTF-16 projection limits independent of schema: id400, clientId100, displayName200 and clientType50 code units; required identifiers are nonempty. Each field is projected to a bounded SQL substring(limit+1) before materialization, then .NET UTF-16 length validation rejects overflow for the whole response. PostgreSQL counts Unicode characters in substring, so supplementary characters can materialize at most2*(limit+1) UTF-16 units; the final limit remains unchanged. No raw unbounded native entity is materialized. Downstream and serialized response bytes are capped at512KiB, including JSON escaping. Oversized/invalid persisted metadata fails closed, never truncates identity.

400 bounded Problem Details for invalid input;401 authentication required;403 current permission denied;503 unavailable/deadline/malformed dependency. Fixed safe problem types/titles and correlation ID; no input/token/connection values. All responses no-store/nosniff. No HTML auth redirects, redirects from upstream, cookies forwarded upstream or browser bearer authority accepted. Data cleared before replacement requests and on failure/expiry/navigation/logout. Server-held expired access credentials require fresh sign-in while local session status may remain authenticated.

Wire documents remain generated from authoritative C# endpoints. Browser TypeScript is generated solely from the BFF projection. Vendor docs routes remain dormant; no unsafe viewer activation is included.
