# Application editor contracts

## Management and browser surfaces

Admin API `/api/v1/applications`; same-origin BFF `/bff/api/v1/applications`. Retain collection GET unchanged. Add GET `/{id}`, POST collection, PUT `/{id}`, and POST `/{id}/secret-replacements`. API requires the actual native bearer plus current per-operation permission; browser uses current protected cookie/session-generation and native antiforgery for mutations. A bounded token-acquisition GET returns only a native antiforgery request token, never OAuth material. Fixed downstream routing; no arbitrary destination, cookie/bearer forwarding from browser, redirects or retries.

Create input: clientId, displayName, redirectUris and credentialExpiresAt. Profile is fixed managed confidential web/code/S256/openid; no arbitrary grant/scope/key/property fields. Update input: displayName and redirectUris only. Replacement input: explicit confirmation and credentialExpiresAt; require current If-Match. Client ID has 1–100 UTF-16 units, no whitespace/control characters, exact ordinal comparison, no trimming/case folding. Display name is 1–200 UTF-16 units, no controls. Redirects: 1–10 distinct exact absolute HTTPS URIs, each at most 2,048 characters; no userinfo, fragment or whitespace/control characters; reject noncanonical/ill-formed input, retain exact native matching. Expiry uses exactly `yyyy-MM-ddTHH:mm:ssZ` (UTC, whole seconds), strictly future at commit; no implicit duration/default. Reject unpaired UTF-16 surrogates in every string, rather than allowing serializer/database replacement. Strong ETag grammar is one quoted lowercase SHA-256 hex digest of the exact UTF-8 application ID, a hyphen, and canonical positive decimal aggregate revision. Missing If-Match returns428; weak tags, wildcard, lists, duplicates, malformed/noncanonical tags and mismatches return412.

JSON bodies are at most 32 KiB, reject duplicate/unknown properties, null/missing required fields and unsupported media/framing. Responses stay within the existing 512 KiB boundary. Field errors use fixed field names/codes with no submitted value echo. All routes no-store/nosniff, API failures never HTML redirects. Managed editable details/update responses include a strong aggregate ETag; unmanaged/system details deliberately have no aggregate ETag; expose it through same-origin BFF unchanged after validation. 400 invalid,401 authentication,403 permission,404 missing,409 duplicate/domain/system-protection conflict,412 stale/malformed precondition,428 missing precondition,503 unavailable/ambiguous mutation. One-time creation/replacement output includes the generated secret only in that successful response; later details/list omit it entirely.

## T007 implemented JSON boundary

The implemented acquisition route is `GET /bff/api/v1/applications/antiforgery`, returning only `{ "requestToken": "<native antiforgery request token>" }` with no-store/nosniff. It requires the current protected BFF session, accepts no body/query or browser Authorization, and does not renew durable state. Native additional data binds a distinct application purpose, browser digest and generation. JSON mutations require exactly one bounded `X-CSRF-TOKEN` header and exact same-origin admission. Existing form-only login/logout and reconciliation proofs cannot substitute for this token family; form mutation admission rejects the JSON header.

T009 maps POST create and GET details in the selected API/BFF application graph; PUT and replacement handlers await T016. Their original five-second budget covers admission, durable reads, native antiforgery validation, one HTTPS send, response validation and publication. Input retains the validated original UTF-8 bytes; output must match the submitted action/fields, exact target and expected aggregate revision. Upstream private headers/cookies and error bodies are discarded. A final durable observation and post-serialization deadline check can suppress output after an ambiguous remote commit; there is no retry or recovery of one-time plaintext. ## T008/T009 create and details

POST collection now authenticates an actual native bearer independently at the API, requires current applications.write in the owned transaction, and returns the generated secret only after native/policy/audit commit and actual cleanup. BFF POST uses the existing genuine native CSRF and fixed transport. Both final response publications recheck original deadlines after serialization; no ambiguous failure triggers a retry.

GET `/{id}` requires current applications.read and uses rollback-only ownership. Managed details return the exact aggregate ETag and selected metadata; expired credential dates remain inspectable for recovery and do not imply issuance authority. Native-profile or policy corruption fails closed. Unmanaged/system registrations return a bounded read-only summary with empty redirects, null profile/credential, editable=false and no ETag. Native hashes, JWK contents and arbitrary properties are never loaded for this projection. IDs are compared ordinally after indexed native lookup on both providers.

The BFF's existing literal `GET /applications/antiforgery` is reserved for native token acquisition. A pre-existing native ID equal to `antiforgery` ignoring case (the router matches literal paths without case sensitivity) is not addressable through BFF GET details; it remains listable and readable through the protected API. Do not use encoded route aliases to bypass the reservation. Newly created native IDs use the native manager's generated identity. The workspace must not promise a details action for this reserved historical ID. No general GUID-only assumption is applied to other native IDs.

## Issuer

Use existing native authorization/token endpoints and discovery; no new grant is advertised. Managed profile: confidential web, code response/query, PKCE S256, native client_secret_basic, scope exactly openid, explicit consent and fresh password/MFA per new interaction. No PAR/private-key substitution, refresh, arbitrary prompts/response modes/scopes/resources or admin audience. Native request caching provides its opaque request_uri. Managed UI resume URLs reference only the native validated cached request; no free-form external return URL.

Password/MFA/consent are distinct exact-purpose Razor pages and protected same-origin POSTs with host-only correlation and original expiry. Consent renders current bound application identity and stable-subject disclosure only. Denial and success complete through native protocol handlers/formatters. Authorization and exchange recheck current application version, secret expiry and account/factor state; native code redemption remains durable before later issuance.
