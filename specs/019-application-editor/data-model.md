# Application editor data model

Native OpenIddict Application remains authoritative for ID/client ID, display name, exact redirects, protocol permissions/requirements and manager-hashed secret. Never duplicate native permission sets as a second policy authority.

## ApplicationPolicy

Key: native ApplicationId (string, supported managed identifier limit 400; native PG text/SQL nvarchar450 schema remains unchanged); fixed profile `managed-web-v1`; aggregate Revision and CredentialRevision (positive portable long concurrency markers); CredentialIssuedAt, CredentialExpiresAt and ObservedAt (UTC Unix seconds). New records start revision 1. Every edit/replacement advances aggregate revision; replacement additionally advances credential revision. Expiry must exceed observed issuance time. Client ID is immutable. No automatic adoption of existing native/system rows. Protect reserved client identities and persisted administrator/pilot application bindings independently. No destructive cascades into audit/replay history.

The safe details projection supplies ID/clientId/displayName/redirectUris/profile, credential metadata, editable status, aggregate ETag and original observation deadline. Never project native secret hashes, arbitrary properties, private keys or plaintext later.

## ManagedLoginInteraction

Opaque unique public selector; native ApplicationId; aggregate revision; exact native cached request-token ID; bounded canonical typed demand digest; browser proof digest; original creation/expiry/retention boundaries; state and portable revision. Authentication binding includes a distinct managed-purpose ceremony ID, verified user ID, account authentication generation, factor generation, enrollment revision, stamp and actual password/MFA completion times. No AdministratorSession ID or BFF establishment grant.

States are PendingPassword=1, PendingMfa=2, PendingConsent=3, Approved=4, Consumed=5, Denied=6 and Expired=7. Successful transitions are pending password → pending MFA → pending consent → approved → consumed; denial and expiry are terminal alternatives. Each transition compares current version, original browser/native demand and deadline. Terminal/replayed/foreign rows cannot reopen. Code principals bind the managed interaction/application revision; edits/replacement invalidate stale pending or issued-code admission. Bound concurrent live interactions per browser and globally, prune only expired terminal data after native replay windows, and fail closed on capacity rather than evicting live rows. Use named bounds: original300 seconds, per-browser8 live, global128 live, total10000 retained, cleanup100. Reserve before native cache creation, bind its actual token ID before commit, and retain for at least14 days plus all associated native lifetimes/skew/30-second rollback grace. Expired unfinished rows become terminal. Independently bound native artifact creation using exact row deltas. Test equality, overflow, concurrent reservation, lost initial redirects and dependent-artifact cleanup.

The selector is stored only as a bounded digest. CeremonyId is a nullable GUID; native application/request/code/authorization IDs are bounded to 400 characters, UserId retains the native 450-character bound and SecurityStamp retains 256. Phase checks prohibit premature proofs and require ordered password/MFA/consent timestamps within the original deadline. Consumed rows retain both native authorization and code IDs; other states cannot carry either. Nullable unique indexes bind each request, ceremony, code and authorization to at most one interaction (explicit filtered indexes on SQL Server).

A pre-cache reservation temporarily has no native request ID or native times during manager saves. T010–T012 must require the actual request attachment before the owning commit; the relational shape alone grants no authority. RequestExpiresAt records the original native request deadline. NativeDependencyCreatedAt and NativeDependencyExpiresAt independently retain the greatest observed native creation and expiry boundaries; the owning transaction extends RetainUntil before publishing dependent artifacts. These observations never renew the original human deadline. Cleanup expires unfinished rows only and cannot turn consumed rows into an unbound state.

Revision and ObservedAt are independent optimistic concurrency guards on both tables; CredentialRevision is additionally guarded on ApplicationPolicy. Watermark-only writes cannot advance the public aggregate version. ObservedAt may pass credential expiry so expired metadata remains inspectable and replaceable. Runtime ownership, monotonic updates, original-deadline enforcement, minimum retention and bounded cleanup remain T006/T010–T012 responsibilities, not claims made by static constraints.
