## Implemented boundary

A genuine native restored managed authorization request now redirects to the fixed issuer-local `/account/application/sign-in` Razor page. The page is registered only with both administrator and managed capabilities in the existing explicitly enabled local-demo composition. It uses the shared account theme, native Razor antiforgery and a separate Data Protection purpose for its bounded `Flow` handle. Each form binds the original browser, managed selector, native request, immutable demand, phase/revision, correlation and original absolute expiry. Exact HTTPS/raw route, same-origin POST, scalar field sets and query rules are checked independently of antiforgery. No posted account identifier, callback, scope or subject becomes authority.

The flow requires a newly verified password, an unused native authenticator code and an explicit Allow or Cancel POST. An existing issuer authentication cookie cannot substitute for either proof. GET reads never approve consent. Current account enablement, enrollment, suspension, security stamp, authentication/factor generations, enrollment revision and lockout are checked under the shared ordered locks. Application policy/revision, native cached-request status and credential expiry are rechecked throughout. The five-minute human deadline remains the original T010 deadline, including a password accepted in its last live second.

The lower native ceremony primitives are reused under the distinct `managed-application-login` purpose. Password failures and MFA/replay failures share the existing account budget; password-only success does not reset it. OTP replay remains common across administrator and managed purposes. Generic administrator completion, ticket issuance and governance/maintenance commits cannot complete this managed ceremony. No administrator session/cookie, issuer completion grant, BFF ticket, authorization code, access token or ID token is created by T011.

One real `ProtocolStorageTransaction` owns each human phase. A private receipt follows actual governance → admission → existing browser-budget → account lock acquisition. A borrowed `CeremonyTransaction` adapts shared native credential operations only inside the current owned execution; it cannot commit, dispose or replace the real transaction. Its lease and token are released before leaving that execution. The managed coordinator snapshots immutable request/account authority before native helpers and their internal saves, verifies both tracked and independently loaded persisted state, and then saves only the intended phase delta with a finite audit event. The exact new ceremony is also frozen around its internal save. A private lexical observation preserves native password-hash upgrades: actual Identity verification must report `SuccessRehashNeeded`, and the exact native-generated hash/security-stamp successor is frozen before the native update, acknowledged successfully and independently checked after persistence. Other stamp/hash changes remain denied. Ordinary administrator verification retains its existing native path. Final reads and the earliest human/credential deadline precede commit.

Razor output and redirects remain buffered through native response callbacks and actual scope cleanup. Frozen output and the original publication deadline are checked before transport publication. Precommit failures roll back proof, replay, budgets and audit. A lost commit acknowledgement or cleanup failure can leave a completed phase durable while withholding the entire response; the stale form cannot repeat that phase. There is no automatic credential retry.

At this checkpoint, approval/cancellation ends in durable `Approved`/`Denied` state. The anonymous cached native request remains valid and unconsumed. **Native code/token issuance is T012**, including separately committed request/code consumption before any later issuance failure. The current terminal page does not claim that sign-in credentials have been issued. Full created-client journeys are T013; the visible create/details UI is T014.
